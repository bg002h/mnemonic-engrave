### C-2 — The "13 are v0.14-era wire version 2" premise is false. They are current single-payload md1 strings, and the gate silently drops 20% of the corpus while asserting the gap

**Task/step:** Task 0, Step 2 (and Step 3, which inherits the same 52/13 split).

The plan's central factual claim, stated as MEASURED and as a correction of both r0 and its
reviewer:

> The 13 header-less files are not a different header shape — their payloads are **v0.14-era
> wire version 2**, which the shipped decoder does not support at all.

and the skip rule built on it:

```rust
Err(Error::WireVersionMismatch { got: 2 }) => { skipped.push(name); }
```

**This is not what those files are.** `crates/md-cli/src/cmd/vectors.rs:70-87` writes
`<name>.phrase.txt` in two different shapes depending on the vector's `force_chunked` flag:

```rust
let phrase_text = if v.force_chunked {
    ... format!("chunk-set-id: 0x{csid:05x}\n") + the N chunk strings   // a CHUNK SET
} else {
    md_codec::encode::encode_md1_string(&descriptor)?                    // a SINGLE PAYLOAD
};
```

Measured in `crates/md-codec/src/test_vectors.rs`: `force_chunked: true` = **52**,
`force_chunked: false` = **13** — exactly the 52 header-carrying / 13 header-less split. These
13 are freshly regenerated by `md vectors` on every run of C-1's corpus test; they are as
current as the other 52.

`reassemble` is the chunk-set reader. Handing it a non-chunked single payload makes it read
the first symbol under chunk-header rules; the `got: 2` is that **misread**, not a version.
`decode.rs:191-193` shows the real dispatch — a single string is routed to `reassemble` only
when the chunked flag is set:

```rust
let chunked_flag = bytes.first().map(|b| (b >> 3) & 0x01).unwrap_or(0);
if chunked_flag == 1 { return crate::chunk::reassemble_with_opts(&[s], opts); }
decode_payload_with_opts(&bytes, symbol_aligned_bit_count, opts)
```

Reproduction (throwaway `examples/` probe, since removed; the tree is clean):

```
reassemble only:                    total=65 ok=52 skipped=13   Tr=20 (is_nums 9 / slot 11)
reassemble, else decode_md1_string: 65/65 decodable, 13 rescued  Tr=23 (is_nums 10 / slot 13)
rescued = [nums_taproot, pkh_basic, sh_wpkh, sh_wsh_multi, single_string_boundary,
           tr_keyonly, tr_with_leaf, wpkh_basic, wsh_divergent_paths, wsh_multi_2of2,
           wsh_multi_2of3, wsh_sortedmulti, wsh_with_fingerprints]
```

`md_codec::decode_md1_string` is public (`lib.rs:54-57`).

**Why it matters.** Three ways:

1. The byte-equality golden — the plan's own words, "the whole gate for this task" — omits
   **13 of 65 vectors (20%)** for no real reason, including **3 of the 23 `Body::Tr`
   vectors**: `nums_taproot` (the canonical NUMS + `multi_a` shape, and the one vector named
   for the flag being refactored), `tr_keyonly`, and `tr_with_leaf`.
2. `assert d["ok"]==52 and d["skipped"]==13` **entrenches** the gap. The assertion was added
   in response to r2 MIN-18 to catch population drift; as written it fires on anyone who later
   widens the reader correctly, so the correction reads as a regression.
3. `Err(Error::WireVersionMismatch { got: 2 })` is precisely the swallowed error the plan's
   own paragraph promises to avoid — it swallows a wrong-reader error, uniformly, for 13
   healthy vectors. The literal `2` is a coincidence of what the misread nibble currently
   holds; it is not a property of anything, so a future payload change turns the skip into a
   `panic!("unexpected decode failure")` on a vector that was never broken.

The plan's paragraph asserting this corrects r0 *and* its reviewer means a wrong fact has now
survived a fold and is stated with more confidence than the thing it replaced.

**ready for implementation: no**

Two Criticals and eight Importants are open. The refactor's *design* is sound — the sum type
is the right shape, the write and read ports are bit-faithful, `compose/tr.rs` is equivalent,
and `load_vendored_phrase` works against both real file shapes. What is not ready is the
apparatus around it: the fixture is placed where it breaks an existing test (C-1), the gate's
corpus rests on a false premise that discards a fifth of the vectors and asserts the gap
(C-2), the golden has three incompatible formats (I-1), and the acceptance step names the
wrong number (I-4) while running a third of the repo's own gate (I-5).
