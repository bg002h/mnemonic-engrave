## Surprises / risks for the S3 plan

1. **The spec's "three secret forms" (words, SeedQR, ms1) do not map onto three code paths today.** `engraveSeed` produces one plate carrying BOTH words and a SeedQR for any BIP-39 mnemonic (`backup.Seed`); there is no existing "words-only, no QR" or "QR-only, no words" plate for a mnemonic. If §7f intends the operator to pick among three genuinely distinct outputs, S3 needs new plate-selection logic (a real fork), not just a `ChoiceScreen` wired to the two existing engrave functions — reusing `engraveSeed` as one arm and `engraveCodex32` as the other only gives two choices, and both are word-bearing/string-bearing single-plate designs, not a films-apart words/QR split.
2. **`ChoiceScreen` has zero overflow protection.** `Draw` stacks children with no clip and no bound check against the 232px content box, and `Choose`'s Up/Down only move `s.choice` — there is no scroll offset anywhere in the type. A payload with more keys/cards than fit the box will silently draw off-frame today (nothing currently exercises this because no existing `ChoiceScreen` caller has an unbounded list); the seating pick list absolutely will, so §9 item 7's "paged widget" is not optional polish, it is fixing a real gap in the primitive being reused.
3. **The "flag-screen wiring" device work item (§9 item 4) is likely a no-op.** The F1/F2/F3/F4 warnings fire exactly once, at payload-LOAD time, from exactly 3 call sites, none of which are per-program. Once `progWalletPolicy`'s admission table adds `ClassMnemonic`/`ClassCodex32Secret`/`ClassPassphrase`, the existing `syswLoadFlow` mechanism already covers it — there may be nothing to "wire" beyond the admission-table change itself. Worth confirming with a walk test rather than budgeting new wiring code.
4. **`confirmReviewScreen`'s citation split is worth getting right in the plan.** The function is defined at `multisig_build.go:1877-1939`; `:804` is a call site (`templateConsentFlow`); `:1908-1931` is specifically its pager-icon-gate sub-block. A plan that cites `:804` as "the paged form" would be citing the wrong thing (a caller, not the paging logic).
5. **`policySummaryLines`/`templateConsentLines` line numbers in the task brief were merged from two different spec citations** (`policySummaryLines` def at `:142` vs. its call site inside `templateConsentLines` at `:86`; `templateConsentLines` itself is defined at `:63`). Not a spec defect — the spec's own text (§7e) cites `:86` correctly for `policySummaryLines`'s "one call site"; the merge happened in how this recon's question was phrased. Flagging so the S3 plan's own citations don't inherit the conflation.
6. **`buildMultisigSeedHook` is not the scrub mechanism** (§9 item 11's "scrub-on-exit seam, C14" framing risks this reading). The hook is a test-observation-only seam that never zeroes anything; the actual scrub is `defer reg.scrub()` installed at `multisig_build.go:291`, at the top of the flow before any seed exists. The composer's own seed-registration flow needs its own `defer ....scrub()` at its own flow entry — copying the hook alone would copy the wrong half.
7. **`gui/sim*.go` and a JSON "journeys" directory under `gui/testdata/` do not exist** — the actual journey/emulator machinery is `cmd/emu/`'s WASM+JS walk scripts, and Go-level journey assertions live as ordinary `_test.go` files using `synctest.Test`/`runUI`/`pumpUntil`/`click`. A plan written against "gui/sim*.go" as a citation anchor will not resolve.
8. **The census/plate-ceiling precedent for TEXT/QR descriptor plates already exists and is a search, not a table.** `qrCeilingBytes` (`gui/transaction.go:1359-1389`) computes its ceiling by binary-searching `txqr.EncodeSet` against module-fit, on the refusal path only — this is the right precedent to copy for §13 item 1's "measured, not read off a constant" descriptor plate ceiling, and it already produces the kind of operator-facing message (module size + Structured-Append symbol count + ECC + byte ceiling + remedy) §8's refusal-naming convention wants.
9. **Row-fit numbers for all three new paged screens (stub screen, pick list, consent) are unmeasurable from source alone**, confirming spec §13's own "NOT verified" list rather than contradicting it — `Choice.Size`/`widget.Labelw` sizes only exist at render time. S3's exit criteria correctly gates on an actual emulator/render measurement, not a number this recon (or any static read) could produce.
