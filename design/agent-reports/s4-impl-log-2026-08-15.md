**The reachable subset, stated rather than implied.** The model names three
kinds; S4's flow offers a choice between two of them, on ONE slot — the
operator's own slot @S is `derived` or `both`, every other slot is `payloadKey`.
`derived` at a non-self slot is multi-slot self, which is S5. The gate accepts
the full model and its tests drive it directly, which the plan schedules rather
than excuses (S5 test 8: *"S2's interim refusal means a divergent-origin input
cannot reach the gate during S4, so every S4 gate test is necessarily
synthetic"*).

**`both` on the SELF slot is the shape the payload actually carries**, and it is
why the flow works out as it does. `cmd/emu/sysw_cards_payload.go`'s provenance
comment names the honest case as *"card A@0's key genuinely derives from the
ClassMnemonic record at that card's declared origin"* — A@0 is at the shared
origin and the payload's only mnemonic is master A's, so the only slot that can
hold both a seed and a key is the operator's own. `buildPolicyParams.SelfFromCard`
carries it; the zero value is the shipped behaviour, so no existing caller or
test literal moved.

## 4. What the walk found, and the Go tests did not

**The gate's FAIL screen was truncated on the rendered frame.** The message named
the likely causes, said reassigning SUPPRESSES the check, and named the host
route — and `TestGateFiresOnBothSlotMismatch` asserted all of that, correctly, on
the string. The emulator's first frame ended:

```

```

`ErrorScreen`'s body scrolls (`gui.go`, `Warning.Layout` binds Up/Down and
fade-clips the overflow) and the text ran past the fold. There is **no scroll
affordance on that screen**, so the operator meets a refusal whose only
constructive remedy is below a fold nothing mentions. That is plan §0.1 clause
3's rule for the confirmation surface arriving one screen earlier, and it is the
same shape as the constraint the text exists to satisfy.

Fixed by trimming both refusals (mismatch 606 → 422 chars; fingerprint 636 → 478)
and pinned by `TestGateRefusalsAreDrawnWithoutScrolling`, which asserts on the
**first** frame — `pumpUntil` would advance past it, and scrolling would prove

**Recorded honestly:** a +65-character mutation still fits (487 total) and did
NOT turn the test red; +160 (569 total) did. So this test pins *"it draws today"*
and not a margin. The fold is a layout property, not a character count, and an
assertion on the rendered frame is the honest guard — a length limit would be a
constant nobody re-measures, which is this project's F-163 construct.

## 5. The emulator walk

`cmd/emu/walk_s4_gate.js`. One driver, one payload, **one different tap** — which
is what makes the fail arm a negative control rather than a second walk.

At n=2 the payload over-supplies (four cards, two open slots), so the picker runs
and the arms differ only in whether payload card 1 — the operator's own A@0 — is
USED or SKIPPED:

```
pass  use:1 skip:2 skip:3  ->  @0 = A@0, @1 = C@0   master A derives A@0's key
fail  skip:1 skip:2        ->  @0 = B@0, @1 = C@0   master A derives nothing of B@0's
```

**Why n=2 and not 3**, stated in the file because it is a constraint: the fail arm
must put a foreign card in the operator's own slot, and at n=3 the only route to
that with this payload lets A@1 land at @0 — which **S2's interim foreign-origin
refusal catches first**, at a different screen, for a different reason. At n=2
both arms' cards sit at the shared origin, so the only thing that can separate
them is the gate.

## 6. The four prose constraints

1. **No spec language on screen.** The question is *"Is your @0 key on a card?"*
   with `NO, JUST MY SEED` / `YES, CHECK THE CARD`. The review reads *"@0 yours:
   payload card 1, checked against your seed for @0"* / *"@1 a cosigner: payload
   card 4, taken as supplied"*. `payloadKey`, `derived` and `both` appear nowhere
   an operator can see them.
2. **Every comparison must be performable — so none is asked for.** The review
   states what the device checked and what it took on trust, which is a claim
   about the device and needs nothing from the operator. No fourth instance of
   the "verify X" defect was added. The shipped *"match your coordinator"* line
   on the Policy Review was **not** touched: the plan assigns that rewrite to S5,
   where the per-slot keys become visible.
3. **The FAIL screen does not make silencing it the obvious next move.** It names
   the causes, says *"Reassigning this slot SUPPRESSES the check rather than
   fixing it"*, and names `me sysw pack` — and §4 above is the record of making
   that true of the *pixels* and not only the string.
4. **Plate count before, inventory after.** Both derived through
   `bundlePlatePlan`, the function `bundleEngrave` itself loops, so neither can
   drift from what is cut. The census screen aborts the build on Back, before
   anything is engraved.

## 7. Judgement calls, flagged

1. **`both` is offered on the SELF slot only, and only when the payload can fill
   it.** The question is drawn when `len(supply) >= n`, following this package's
   own rule that a picker with one possible answer teaches nothing
   (`syswSeedPicker` says so in those words). The consequence is that the number
   of screens depends on payload contents. The alternative — always asking —
   walks the operator into an under-supply refusal they caused by answering a
   question the device already knew the answer to.
2. **The walk-away bound: this flow is NON-WIPING, and the restore doc says so.**
   The plan gives two arms and forbids silence. I took the recorded-decision arm.
   An idle timer would fire on an operator reading that very document and discard
   hours of work, and the registry holds exactly one seed today — the same
   exposure the shipped flow had, so a timer would buy no reduction over the
   state of the tree. **This should be re-decided at S5**, which is where the
   registry actually holds several masters. Filed below.
3. **The registry drops the passphrase rather than overwriting it.** A Go
   string's backing bytes are immutable, so nothing can zero them in place; the
   reference is released and the collector reclaims it. This is exactly the
   property the shipped flow already had. Said in the code rather than implied.
4. **`assembleBuildPolicy` skips the self-key derivation on a `both` slot.** M-B
   makes the card authoritative and the gate has already proved the two agree, so
   deriving a second copy of the same key would only create a second thing that
   could be wrong. The engrave tail still derives the leg from the seed at
   `multisigSharedOrigin()`, which during S4 is the same path every card
   declares (S2's refusal guarantees it).
5. **Three structural guards were widened, not relaxed**, and each would
   otherwise have left a real door open rather than merely gone stale:
   `TestNoVerifyFlowCanReachAPayloadSecret` (a verify flow calling
   `seedEntryFlowTitled` reaches the payload exactly as far as one calling
   `seedEntryFlow`), `TestEverySyswConsumptionSiteNamesAnAdmittedClass` (the
   `take()` moved into a `...Titled` variant the exact-name matcher could not
   see), and `TestTheSeamPassphraseOfferReachesOnlyProgramsThatAdmitIt` (same
   shape, and its `forbidden` list is what keeps ClassPassphrase out of Backup
   Wallet and the two verify flows). `TestTheChecksumGateIsOnForSeedEntry` was
   keyed to a whole struct literal and is now keyed to the field.
6. **Commit seams.** Four commits, not the five the brief's list implies. The
   slot model, the registry and the gate are one change in one file plus one flow
   function, and splitting them would have produced a non-compiling intermediate.
   The plumbing (`6bbe6d2`) and the walk (`ecb1245`) split cleanly; the fold fix
   (`27547a1`) is its own commit because the walk is what found it and the diff
   should say so.
