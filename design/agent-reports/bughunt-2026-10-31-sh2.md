## Confirmed bugs (worst first)

### High

**1. A different xpub is engraved from the one that was entered** (demonstrated)
- Where: `bip380/bip380.go` `Key.ExtendedKey` / `ParseKey`, around lines 97-109 and 366-424. `ParseKey` throws away the xpub's depth and child number. `ExtendedKey` then rebuilds them from `DerivationPath`, which is the implied script path when the key has no origin.
- Input: `wsh(sortedmulti(1,<depth-0 xpub>,…))` with no key origin, or any origin whose length doesn't match the xpub's real depth.
- Should: re-encode the same xpub that was entered.
- Does: produces an xpub with depth 4 and child 0x80000002, a different base58 string with a different checksum. The device engraves an xpub the user never supplied.
- Test: `prover-14/repro/repro_test.go`.
- Fix: keep `Depth` and `ChildNumber` from the parsed xpub and use them when re-encoding.

**2. Single-sig: cancelling the passphrase entry quietly continues with no passphrase** (confirmed by reading)
- Where: `gui/singlesig.go` `singleSigInputs`, around line 134. `step = stepMode` runs even when `syswPassphraseFlow` returns `ok=false`.
- Input: choose "Add passphrase", then press Back or cancel on the keyboard.
- Should: go back to the passphrase question. The step-machine doc says "Back means back".
- Does: derives and engraves the wallet **without** the passphrase the user said they wanted, with no warning.
- The same pattern appears in `gui/singlesig_verify.go:138` (rated 2, not proved), and is reported in `derive_xpub.go:432` and `multisig.go:150` (not checked).
- Fix: `if !pok { continue }`.

**3. BIP-85: cancelling the passphrase entry derives the child from the master without a passphrase** (confirmed by reading)
- Where: `gui/bip85.go` `bip85DeriveFlow`, line 335. This is the same pattern as #2.
- Does: the engraved child seed belongs to a different master than the one the user chose.
- Fix: stay on the passphrase step when the entry is cancelled. Under `refugiumProfile` the flow also returns `("", false)` on purpose, so the fix must keep that case working.

### Medium

**4. Typed seed entry returns a half-typed mnemonic as confirmed** (confirmed by reading)
- Where: `gui/derive_xpub.go` `seedEntryFlowTypedOnlyTitled`, line 226. It ignores the `confirmed` bool from `inputWordsFlow` and only checks whether the mnemonic is empty.
- Input: choose 12 words, type 3, press Back.
- Should: treat Back as backing out.
- Does: returns the mnemonic with words 4–12 set to -1, marked as confirmed. Callers derive from it or fail on the invalid words. The sibling `…Resume` function has a comment warning against exactly this.
- Fix: use the returned bool.

**5. md1 chunk gatherer accepts a chunk index past the total, leaving a gap** (demonstrated)
- Where: `gui/md1_gather.go` `offer`, line 58. `md/chunk.go` `readChunkHeader` also doesn't reject `index >= count`.
- Input: a 2-chunk set made of chunk 0 and a crafted or corrupted chunk with index 5.
- Should: refuse the bad chunk.
- Does: `complete()` returns true, and `collected()` has `""` where chunk 1 should be. The operator is never asked for the real chunk 1.
- Test: `prover-28/repro/md/oob_gather_test.go`.
- Fix: bounds-check the index in `offer` and in `readChunkHeader`. `mk1Gatherer` should be checked for the same gap.

**6. A multisig threshold of 0, a negative number, or more than the key count is accepted** (confirmed by reading)
- Where: `bip380/bip380.go` `Parse`, around line 340, and `nonstandard/parse.go` `parseBlueWalletDescriptor`, line 107.
- Input: `wsh(sortedmulti(5,A,B))`, or BlueWallet `Policy: 0 of 2`.
- Does: returns a descriptor with that threshold. `sysw/descriptor.go` checks the threshold itself, but `gui/scan.go`, `gui/wallet_policy.go` and `seal/record.go` were not seen to.
- Also: `bip380.Parse` accepts `sortedmulti` under `pkh`, `wpkh` and `tr`, and accepts `wsh` with a single key.
- Fix: require `1 ≤ k ≤ n`, and check that the script type matches.

**7. The picobin image hash uses entry 0's size for every zero-fill LOAD_MAP entry** (demonstrated)
- Where: `picobin/picobin.go` `HashData`, line 328. It hashes `eidx+8` where it should hash `eidx+i*12+8`.
- Input: a LOAD_MAP where an entry other than the first has `storage_start==0` and a different size from entry 0.
- Does: the computed hash differs from the bootrom's, so a signed image fails secure boot, or a mismatch goes unnoticed.
- Test: `prover-12/sh/picobin/lm_test.go`, run in the package.
- Fix: hash `eidx+i*12+8`.

**8. NFC Type 2 reads stop at 848 bytes on large tags** (demonstrated)
- Where: `nfc/type2/type2.go` `Reader.Read`, line 131. The block counter is a `uint8`.
- Input: a tag with CC size byte 0xEA, e.g. NTAG I2C 2k.
- Does: returns EOF after 848 bytes, silently dropping the rest of the NDEF data.
- Test: `prover-11/repo/nfc/type2/large_test.go`, run in the package.

**9. One oversized NFC read breaks scanning until restart** (demonstrated)
- Where: `gui/scan.go` `scanner.Scan`, line 36. The overflow flag is never cleared.
- Does: after one read fills the 8 KiB buffer, every later scan returns `errScanOverflow`.
- Test: `prover-17/sa/scan_test.go`.
- Fix: clear the flag once the oversized content ends.

**10. Malformed UR fountain QR codes crash the device** (demonstrated, 4 separate bugs)
- Where: `bc/fountain/fountain.go` `Decoder.Add`.
- Inputs and effects:
  - `SeqLen=0` → index-out-of-range panic (`prover-2`).
  - Fragments with different `Data` lengths → panic in `reducePart` (`prover-3`).
  - `SeqLen=1<<31` → tries to allocate tens of GB and runs out of memory (`prover-19`).
  - `SeqNum=0` → the fragment index becomes 2³²-1, and the decoder is stuck forever or fails with a checksum error (`prover-33`).
- Fix: in `Add`, check `1 ≤ SeqNum`, `1 ≤ SeqLen ≤ cap`, and `len(Data) == ceil(MessageLen/SeqLen)`.

**11. `codex32.New` panics on a long prefix with a short data part** (demonstrated)
- Where: `codex32/codex32.go` `partsInner`, line 167.
- Input: `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa10leetwl7wjd64zfny6`, which has a valid checksum.
- Does: panics with "slice bounds out of range [6:5]".
- Test: `prover-9/sh/codex32/shortdata_test.go`, run in the package.
- Fix: `if len(res) < 6+checkLen { return errInvalidLength }`.

**12. `bip39.Mnemonic.Valid` panics on an empty mnemonic or one of 27+ words** (demonstrated)
- Where: `bip39/bip39.go`, line 150.
- Does: index `[-1]` for empty input; "entropy too long" for 27 words, which `ParseMnemonic` can reach.
- Test: `prover-4/sh/bip39/valid_panic_test.go`, run in the package.
- Fix: return false when the length is 0 or over 24.

**13. `WriteWhiteLabelString` miscalculates free OTP space, so new strings overlap old ones** (demonstrated)
- Where: `driver/otp/otp.go`, line 253. It checks `switch idx` where it should check `switch uint8(i)`.
- Input: an existing UTF-16 product string at entry 5, and a new string written at entry 8.
- Does: the new string starts at row 21, overlapping the product string. **OTP is write-once, so this cannot be undone.**
- Test: `prover-24/repro_test.go`.

**31. Multisig: cancelling the passphrase entry, or pressing Back on the passphrase question, continues with no passphrase** (demonstrated; confirmed independently by 7 provers)
- Where: `gui/multisig.go`, around lines 143-153. The code is `if sel, ok := askBIP39Passphrase(…); ok && sel == 1 { if pass, ok := syswPassphraseFlow(…); ok { passphrase = pass } }`, and neither failure path returns.
- Input: choose "Add passphrase", then press Back on the keyboard; or press Back on the "Add a BIP-39 passphrase?" question.
