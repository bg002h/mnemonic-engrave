## 1. The mechanism, re-measured — and it is worse than "blanks its own line"

Your brief said the body blanks. I measured it on the production line builder
rather than taking it, because the Payload Warnings screen builds its body from a
**list** of independently laid-out labels, and per-line blanking was the
plausible alternative. It is not what happens.

`syswLoadWarnings` over a payload holding a seed **and** a lone md1 chunk emits
two lines: `"A SECRET is stored unencrypted in flash."` (clean ASCII) and
`"An md1/mk1 the device could not confirm — treated as a secret — is stored
unencrypted in flash."` (two em-dashes). Rendered through `confirmReviewScreen`:

| body | ink |
| --- | --- |
| empty body | 5815 px |
| clean line only | 7442 px |
| broken line only | 5004 px |
| **BOTH, exactly as production emits them** | **5004 px** |
| broken line with hyphens | 9353 px |

**Both lines together render exactly what the broken line alone renders.** The
em-dash did not blank its own sentence — it blanked the *sibling* sentence
telling the operator a seed is sitting unencrypted in flash. The clean, correct,
pure-ASCII, most consequential line on the device was collateral damage from a
punctuation mark in the line next to it.

That is why I chose that pair as worst case (1) and why this is not a typography
change. Your framing was right; the granularity is worse than "per line" and I
would not have believed it without the table.

### What the guard is

A **face-coverage lookup**, per your instruction, not a blocklist. For every
string literal in every non-test `gui/*.go`, every rune must satisfy
`GlyphAdvance` on **all ten** faces, with `\n`/`\t` allowed explicitly.

`TestEveryFaceRejectsNonASCII` pins the premise rather than trusting the comment:
`font/bitmap/bitmap.go:33` sets `indexLen = unicode.MaxASCII` and `glyphFor`
rejects `int(r) >= indexLen` at `:62`, so face choice really is immaterial. The
test asserts every face has `'A'` and lacks `— · ✓ … → ⌫` and `rune(127)`. If a
face ever widens, that test goes red and every ink floor in the package needs
re-measuring — which is the right thing to be told.

**JUDGEMENT CALL — I parse instead of scanning, flagged.** You said to widen S2's
shape rather than reinvent it. I kept the *shape* (scanner + guard + scanner
vacuity proof) and replaced the *implementation* with `go/parser`. S2's
`stringLiterals` walks characters and skips whole-line comments by prefix, which
(a) mishandles a trailing comment containing a quote, (b) treats a backtick raw
string as ordinary text, and (c) cannot report a line number. The parser excludes
comments **structurally** — they are not in the AST — unquotes raw strings and
escapes correctly, and carries a position. (c) is not cosmetic: it is what lets
gate element 2 name the file and the rune, which you required.

This is also the fix shape for **F-184** (the `cmd/emu` needle counter treating a
commented literal as a production site). I did **not** land that here — it is
`cmd/emu`'s and the S0b fold's.

**JUDGEMENT CALL — I removed S2's blocklist, flagged.** `blankingGlyphs`,
`stringLiterals`, `TestGatherScreenTextCarriesNoBlankingGlyph` and
`TestStringLiteralScannerCanSee` are strictly subsumed: the new guard covers
every production literal in the package rather than three named functions, and
every rune rather than seven. Leaving both would leave the hand-maintained
construct you called the wrong instrument sitting next to its replacement,
inviting the next author to add rune number eight. `gui/bundle_gather_refusal_test.go`
keeps its **drive/ink test** (the only thing there that proves a *reached* screen
draws) and now carries a comment explaining where the guard went and why. If you
want the blocklist retained as belt-and-braces, say so and I will restore it.

## 8. Follow-ups I would file

- **F-185 (Important, owning phase: S0b fold or the next `cmd/emu` change).**
  F-184's fix shape is now demonstrated in `gui/font_coverage_test.go`:
  `cmd/emu/needle_test.go`'s `productionSites` should parse rather than
  substring-match, so a needle quoted in a comment stops counting as a production
  site. I hit this in S3 (a comment quoting `P2SH-P2WSH` made the needle look
  two-sited) and worked around it by not quoting the string. The workaround is a
  discipline; the parser is a mechanism.
- **F-186 (Minor, owning phase: S3b follow-on / any package with drawn text).**
  The guard covers `gui/*.go` only. Any drawn string built outside that package —
  `bundle/`, `engrave/`, or a future package — is unguarded. The check is
  package-local by construction (it reads `.`); making it a shared helper would
  let other packages opt in.
- **F-187 (Nit, owning phase: whenever the font format changes).** The face
  lookup accepts control runes below 127 other than `\n`/`\t` only if
  `unicode.IsPrint` passes, so e.g. `\x07` is rejected — but a rune that *is*
  printable ASCII yet has an empty glyph bitmap would still pass. Not reachable
  today (the faces cover printable ASCII), and `TestEveryFaceRejectsNonASCII`
  would not catch it. Worth knowing if a face is ever regenerated with gaps.
- **F-188 (Minor, owning phase: doc pass).** Your brief and F-179 describe the
  blanking as per-body; §1 above shows that for a **list**-bodied screen the
  broken line also destroys its clean siblings, which is strictly worse and is
  the reason the seed-in-plaintext warning vanished. Worth recording in F-179 so
  the next reader does not re-derive the table.

## 9. What is NOT proven

- The guard is a **source** check. It proves no production literal in `gui/*.go`
  carries an undrawable rune; it does not prove any particular screen was
  reached. The ink tests cover the two screens you named and the keyboard;
  every other screen's *drawing* remains covered only by whatever tests it
  already had, most of which use `uiContains` and are blind to this class.
- Strings assembled at runtime from non-literal sources (a decoded payload, an
  operator's free text) are outside the guard by construction. A card whose label
  contains a non-ASCII rune would still blank a body.
- No hardware was run.
