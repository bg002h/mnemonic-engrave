## 1. Findings — what changed, and the evidence each now fails

### C-1 — the derived-census gate skipped when the oracles were absent

`oracle/expect_test.go` was rewritten into two layers.

**Layer 1, the gate, cannot skip.** `TestEveryGateRecordCensusMatchesIts-
CommittedExpectation` compares every record's census against
`oracle/gaterecords/<base>.expect.json`, which holds the primary's own output.
No binary is invoked and none can be. Absent / empty / unparseable / wrong
schema / unknown JSON field are each a fatal refusal, never a skip
(`LoadExpect`, `oracle/expectfile.go`).

**The three mutation proofs moved onto layer 1.** This was C-1's sharpest
consequence — the skip took out the gate *and* its own proofs together, so the
mechanism had never been seen to fail on the deciding machine. They now run
wherever the gate runs, driven off the committed expectation.

**The live re-derivation is not a test in this build.** `resolveBins` and
`TestLiveDerivationReproducesEveryCommittedExpectation` live in
`oracle/live_test.go` behind `//go:build oraclelive`, together with
`TestRealPinsResolveTheInstalledOracles` — C-1's third site, the stale-pin
backstop that had been sitting behind the same door as everything it backed up.
Inside the tag absence is a hard `t.Fatalf`; there is no skip and no variable.
Its `-short` skip is gone too: `-short` means "keep tier 2 out of the inner
loop", and typing `-tags oraclelive` *is* asking for tier 2.

**Deleted the false justification** at the old `:13-16`: *"The gate that makes
absence fail is `TestS0GateHasARecord`, which does not need the binaries."* The
review proved it false — `TestS0GateHasARecord` checks only that a record
**file** exists and never touches `CompareCensus`. The replacement comment says
what actually enforces the property.

### C-2 — the comparison was hardwired to one filename; a fabricated record passed

Two changes, and the second is the one with teeth.

**The loop.** `loadExpectations` enumerates `Records(GateRecordsDir)` and
**fails on any record without a committed expectation**. The hardcoded
`"S0-trace-a.record.json"` is gone. Added `TestEveryCommittedExpectation-
BelongsToARecord`, which also catches the reverse — an orphan expectation whose
record was deleted still makes the directory look covered — and requires the
expectation's `record` and `stage` fields to match the file it sits beside.

**Minting.** `cmd/gaterecord` now derives live and **refuses to write anything**
when the walk's census is not what the primary just produced. A record cannot
come into existence except as something the primary agreed with. **This is the
one place live derivation is mandatory, and it cannot be turned off by flag or
by environment** — it is what makes "a committed expectation" mean "something the
primary produced" rather than "something somebody wrote down", which is what the
whole toolchain-free layer rests on.

Proof 5 replays the review's own fabricated-S9 scenario and it is now refused.

### C-3 — S2's md1 byte-identity gate skipped by the same construct, in `gui/`

`gui/multisig_build_oracle_test.go` split the same way. The device's assembly is
factored into `s2TraceAPolicy`, shared by both arms, so the two layers cannot
drift.

- `TestAssembledMd1MatchesTheCommittedGolden` — **the gate.** Unconditional,
  no toolchain. Compares the device's six chunks against
  `gui/testdata/s2_md1_golden.expect.json` and checks that golden's provenance
  against `oracle/pins.json`.
- `TestAssembledMd1MatchesThePrimaryByteForByte` — the freshness check and the
  only `-update` mint path, in `gui/multisig_build_oracle_live_test.go` behind
  the `oraclelive` tag. There is no other code path that writes a golden, which
  is what makes the golden trustworthy where no toolchain exists.

**Deviation from the ruling's Question B consequence, flagged deliberately.**
The ruling said this fold's report should record *"the first CI-executed PASS of
`TestAssembledMd1MatchesThePrimaryByteForByte`"*. After this fold that test
**does not exist on CI at all, by design** — it is the live arm. What executes is
`TestAssembledMd1MatchesTheCommittedGolden`, and it compares the same six chunks
against the same primary bytes. The *property* Question B wanted enforced is
enforced; the *test name* in the annotation must change. The continuity doc's S2
line should read that new name.

### I-1 — `census.strings.length === plates` dropped from `ok` in BOTH walks

`cmd/emu/walk_trace_a.js:274` and `cmd/emu/walk_build_policy.js:532`. The count
is reported as `plateCount`, data. `ok` now holds only emulator-observed terms.

**One thing the finding did not mention and I had to resolve:** `plates` is
*also* the engrave loop's stopping bound (`walk_trace_a.js:215`,
`walk_build_policy.js:165`). Deleting the parameter would have broken both
drivers. It stays as a loop bound, documented as one, and the guard below stops
it from creeping back into `ok`.

**I replaced the term with `census.strings.length > 0`, not with nothing.**
Dropping it outright would have made a zero-plate census green — trading a
false-PASS for a vacuity. A non-zero count is emulator-observed; a *specific*
count is not.

### I-2 — the needle gate's two halves now joined by a check

`TestWalkNeedleLiteralsAreAllPinned` extracts every
`export const NEEDLE_* = "..."` from **`walk_*.js` by glob** and requires each
literal to be in `buildFlowNeedles`. Globbed rather than named, per the brief, so
S3's and S3b's future walks are bound the moment they land and needle additions
are a non-conflict.

Blind spot stated in the source: it binds `NEEDLE_*` declarations only, so a walk
calling `waitFor("bare literal")` is invisible — `walk_trace_a.js` legitimately
does that today. The convention is the coverage.

## 4. Judgement calls — things I decided rather than transcribed

0. **The `oraclelive` build tag, in response to the mid-fold directive.** The
   brief and the ruling both specified an opt-out variable. The directive
   forbids it. Of the three honest shapes for a check that cannot run on the
   deciding machine — skip-there, fail-there, not-exist-unless-asked — only the
   third satisfies both the directive and "do not turn CI red", so that is what
   I built. I judged that a build tag *is* the "explicit command a human
   invokes" the coordinator asked for, since the human types the tag (or
   `./scripts/oracle-live.sh`); it is not a runtime branch that can take itself.
   The alternative reading — delete the live checks entirely — would have thrown
   away the only mint path for the S2 golden and the only drift detector for the
   pins, so I kept them and made them unreachable-unless-named.
1. **`-expect-only` on `cmd/gaterecord` (not in the ruling).** The ruling has
   minting write the expectation. Minting S0's expectation the ordinary way would
   have **rewritten S0's committed record**, moving its `recorded_at` to a moment
   when no walk ran. A record is evidence; a derivation is not. `-expect-only`
   re-derives, compares against **both** the walk and the record already on disk,
   and writes only the expectation. It is also the operation the design needs
   anyway: a pin bump makes every expectation stale without making any walk less
   true.
2. **Goldens in `gui/testdata/` and `sysw/testdata/`, despite
   `oracle.CheckDataSource` refusing any `testdata` path as a comparison
   source.** The ruling names those directories. Nothing calls `CheckDataSource`
   on them (grep: definition + its own unit test only), so there is no mechanical
   conflict — but a future reader will hit that function and think the fold
   violated it, so `oracle/expectfile.go` addresses it head-on: `CheckDataSource`
   refuses *"an older and smaller sample of ourselves"*, and every byte in an
   `ExpectFile` came **out of a pinned primary binary**. It is a cached primary
   output, not fork-authored data. That distinction is worth only what maintains
   it, so the file lists the three mechanisms that do.
3. **`TestWalkOkContainsNoDriverSuppliedPlateCount` (not in the ruling).** I-1's
   fix is a deletion, and `plates` survives one identifier away as a loop bound.
   Without a guard the term goes back the next time somebody wants a
   stricter-looking green. Proven to fail (§2).
4. **`ok: census.strings.length > 0` rather than dropping the term entirely.**
   Dropping it outright makes a zero-plate census green. A *specific* count is
   driver-supplied; a *non-zero* count is emulator-observed.
5. **`DeriveExpected`'s signature changed** to return a `DerivedSet` carrying the
   oracles it invoked and the redacted invocation forms. The alternative — a
   table saying which oracles a kind "uses" — is a hand-maintained claim beside
   the code that could contradict it, which is the shape this project forbids.
   Only `oracle/expect_test.go` and `cmd/gaterecord` call it.
6. **Invocation args are RECORDED REDACTED** in gate-record expectations
   (`--phrase <seed words: see the inputs file>`). Seed words on a recorded argv
   would put key material in a committed file and in CI logs — the same refusal
   `SeedRef` exists for. The S2 golden records its argv **in full**, because
   xpubs are public.
7. **`NewExpectFile` / `LoadExpect` refuse empty artifact strings.** This is the
   *shape* of M-2, scoped strictly to the new file format. `CompareCensus` itself
   is **untouched** — M-2 remains open and filed (§5), because folding an
   unrelated Minor into a coupled set is exactly what the brief forbids.
8. **The needle mutation proof used a new `gui/` file, not `gui/singlesig.go`.**
   The review's own mutation site is under S3's fence. Same effect on the
   counter; created and deleted inside one command; `git status` clean after.
9. **`-update` reuses `gui`'s existing package-level `update` flag** (declared in
   `gui/freetext_sizeproof_golden_test.go`, which I only read). Consequence
   found by running it: `scripts/oracle-live.sh` cannot forward `-update` to
   `./oracle/` and `./sysw/`, which do not declare it — the first version exited
   1 with "flag provided but not defined". Fixed by dispatching `-update` to
   `./gui/` alone, with the reason written into the script.
10. **`cmd/gaterecord` requires the inputs file to sit beside the record.** The
    expectation is re-derived from it by basename, so a record whose inputs live
    elsewhere cannot be re-checked. Refusing is honest; copying would have been a
    hidden second source of truth.
11. **The CI compile-check is `go test -tags oraclelive -run '^$'`, not
    `go vet -tags oraclelive`.** I wrote the vet form first and measured it
    before committing: it exits 1 on `gui/freetext_sizeproof_golden_test.go`'s
    pre-existing `testing.ArtifactDir` finding, so it would have turned CI red
    on day one for a reason unrelated to this fold. `go test -run '^$'` compiles
    every tagged test binary, runs nothing, reports `[no tests to run]`, and
    exits 0 — and it is proven to fail on a real type error (proof 4b). It is a
    build step, not a check that skipped.
12. **`ExpectFile.Marshal` disables HTML escaping.** The committed file is
    evidence a human reads in a diff, and `<angle-bracket>` placeholders rendered
    as `<` are unreadable exactly where a reader checks what was run.
