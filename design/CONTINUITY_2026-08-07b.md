## 2. WHAT EXISTS NOW

**Host** (`crates/me-cli/src/seal/`): `me seal` encrypts a payload under a
generated 12-word BIP-39 passphrase and emits a data-family UF2 for
`0x10E00000`; `me hash` re-derives the §6.6 public-data hash months later from
the operator's own cards.

**Device** (`seal/` in the fork): XIP read, §6.2 header parse, §6.4 section
decode, §10.2.1 allow-list, §6.3 card-set decode, §6.6 hash, PBKDF2 →
AES-256-GCM open. **Headless — no UI at all.** Entry points:

- `Inspect(blob)` — §10.2 steps 1–3. No passphrase, no KDF. Yields the hash.
- `Unlock(blob, p, passphrase)` — steps 5–9. A failed call leaves `p` and its
  hash intact, which is what §10.2 step 8's retry loop needs.
- `Open` — the two composed.
- `Payload.Wipe()` — Phase B **must** call it on every session exit path.

**The vector contract is data, not retyped constants.** `seal/testdata/vectors.json`
carries all seven canonical vectors, generated by the normative Rust:

```
ME_EMIT_VECTORS=1 cargo test -p mnemonic-engrave --lib seal::tests::emit_vectors
```

Without that env var the test **asserts the committed file still matches**, so
drift in either direction fails the suite. Never hand-edit it.

## 3. THE HARDWARE RESULT, AND THE TRAP IN IT

Flashed a Pico 2 (chipid `0x66d3d60ff20abf2f`, secure boot on) with
`cmd/sealread`, signed with `rehearsal-work/my-key.pem`. **Verified:**

```
probe @0x10300000 first 16: 4d 4e 45 4d 42 4c 4f 42 01 00 00 00 00 00 00 00
probe header OK — pub_len=203 ct_len=0 sealed=false
```

Byte-exact against what the host wrote; `pub_len=203` independently right
(3 × 67 + 2 LF). So the fixed-address `unsafe.Slice` read and `ParseHeader`
**work on real silicon** — Phase A's one claim with no precedent in the repo and
no host test able to compile it.

**⚠ THE TRAP.** That ran at `0x10300000`, **not** at `PayloadAddr`. A Pico 2 has
**4 MB** of flash; `0x10E00000` is **14 MB** in. The region does not exist there:
`picotool` refuses the load, and an XIP read **aliases** to `0x10200000`. So
`sealread`'s own `no payload at 0x10e00000 — CLEAN state` line is a
correct-*looking* answer from the wrong address. **Do not cite it as evidence
about the normative region.** See **F-73**.

Closing it needs a 16 MB part: a **Pico Plus 2** (`__flash_size=16M`, which is
why the fork's build target is `pico-plus2`) or the SH2. **`pico2-w` does NOT
qualify** — it is `{"inherits": ["pico2"]}`, 4 MB.

**Keys, settled from two directions.** The Pico's OTP trusts
`rehearsal-work/my-key.pem` (X‖Y sha256 `17644fb6…`): the signed image booted
under secure boot, and `picotool` showed the pre-existing image carried the same
pubkey `9EC00C33…`. The SH2 key (`846aa289…`, in `~/.sh2/`) is unrelated and the
Pico does not trust it. **The rehearsal keys live in `mnemonic-engrave/rehearsal-work/`,
NOT in the fork** — an earlier draft of this looked in the wrong repo and
concluded they were gone.

## 4. THE LESSON THIS CYCLE ACTUALLY TAUGHT

**Across 18 Plan A review rounds, 3 Plan B R0 rounds and 4 post-implementation
reviews, not one finding ever landed in the cryptography.** All seven vectors
were byte-exact on first run and reproduced independently in Python. Every
defect was in the reasoning or plumbing around it.

**And the majority were authored by FOLDS, not by original drafts:**

| defect | where it came from |
| --- | --- |
| plan had no §6.4 container task at all | original draft |
| no all-lowercase check — Go's `ValidMD` accepts uppercase *by design* | original draft |
| `AllocsPerRun == 0` demanded alongside a count-naming error (impossible) | **R0 round-1 fold** |
| self-asserting UF2 constants (`FAMILY_DATA`, `TARGET_ADDR`) | plan, survived to code |
| one-token section mis-wiring — 100 tests green, public section admitted seeds | implementation |
| second `Unlock` orphaned the first call's secrets, un-wiped | **whole-diff-review fold** |
| `Unlock` panicked on a short blob | **whole-diff-review fold** |

**A fold is authorship and re-earns the gate.** Persist the report verbatim in
its own commit, fold in a second with the gate output in the message, re-review.
Three of four folds this cycle introduced a defect nobody had looked at.

**The single most transferable rule:** *an assertion is only a pin if its
expected side comes from OUTSIDE the code under test.* `assert_eq!(f(x),
THE_CONST_f_USES)` pins nothing — mutating the constant moves both sides. That
one shape produced the UF2 escape (both destructive constants, `0xE48BFF59` the
bootable-image family and `0x1000_0000` aimed at the signed firmware, survived
the entire 169-test suite) and, in a different guise, the `FileReader` bound
that came from the buffer size rather than from `clampRegion`.

**Two gates earned their keep and should be kept:**
- `scripts/plan-build-gate.sh` — compiles a plan's Rust before a reviewer sees it.
- `scripts/plan-cite-gate.sh` — resolves every `file:line` / `pkg.Symbol` and
  **prints the line**. Caught three of the author's own mis-cited lines on its
  second run. It states its own blind spot: it proves the line exists, never
  that it means what the plan claims.

**Watch what you paste.** Two commit messages this session claimed things that
were never checked — `go vet clean` for a package vet cannot load, and results
whose edit script had thrown `ValueError: substring not found` while the commit
ran anyway because the commands were newline-separated rather than `&&`-chained.
Both corrected in the record rather than amended away. Read output *at* it, not
past it.

## 6. STANDING CHANGES MADE THIS SESSION

- **`go test ./...` in the fork now has TWO sanctioned setup failures**, not one:
  `cmd/kdfbench` and `cmd/sealread`, both TinyGo-only (`machine` is not in host
  std). Anything else is a regression. Update this if another lands.
- **`--seal-secret` covers `ms1` AND a bare BIP-39 mnemonic.** Best-effort
  anti-footgun, **not a security boundary** (operator decision). The device's
  guarantees live in §10.2.1's allow-list and must never rely on it.
- **SPEC §7's AES-GCM rationale was wrong and is corrected.** It credited
  `crypto/ecdsa`, which contributes **0 bytes** (dead-code-eliminated). The real
  path is `bip39 → crypto/rand → fips140/drbg → fips140/aes` plus the FIPS
  self-test registry. Resident ≈ 20.2 KB, marginal ≈ 1.6 KB — not "zero". The
  choice stands; only the reasoning was wrong.
- **Provenance pins are NOT actually maintained**, contrary to CLAUDE.md: `md`
  pins md-codec 0.36.0 (host is on 0.42.0), `mk` pins a coarse "0.2" (host
  0.4.1), and `codex32`/`slip39`/`seedxor`/`bip39`/`bip85` have none. Not fixed —
  bumping a pin asserts a convergence nobody verified.
- Pushes to `mnemonic-engrave` `master` **bypass a required status check**
  (`test (rust + go)`). Happened four times. Land future work via PR if that
  check should actually gate.
