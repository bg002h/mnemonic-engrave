SeedHammer II

Build a Bitcoin wallet policy on a device that isn't here.

Below is the actual firmware — the same Go code that runs on the machine, compiled to WebAssembly. Not a mock, not a video, not a reimplementation of the screens. Tap it and it behaves exactly as the hardware does, because it is the hardware's software.

Pick something to build

Each one ends with a Template-ID: a 128-bit fingerprint of your policy's shape.

Everything here is throwaway test data. The seeds, shares and passphrases on this page are published test vectors. Nothing on this page touches money, and nothing you do here can.

Then try it on your own machine

The device is one half. The other half is a set of command-line tools that compose the same policies, turn them into engravable strings, and check the device's work. Two of them are worth ten minutes of your time.

Install

Needs Rust. Takes a few minutes to compile.

# the descriptor tool — the published build is fine
cargo install md-cli

# the seed tool — from git, NOT crates.io, and the reason matters:
# the published 0.14.0 can only take a seed as a command-line argument.
# Current builds add a private channel (--in FILE) and actively refuse argv.
cargo install --git https://github.com/bg002h/mnemonic-secret ms-cli

1  Split a seed three-of-five, then prove two isn't enough

codex32 (BIP-93) is Shamir's secret sharing over the bech32 alphabet. Five shares; any three rebuild the seed; two rebuild nothing. 

# A published all-zeros test vector. Never do this with a real seed.
echo "abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about" > seed.txt

ms split --in seed.txt -k 3 -n 5 --group-size 0 > shares.txt
# 5 lines, each starting ms13... — different every run, they're randomised

# any three of them
sed -n '1p;3p;5p' shares.txt > three.txt
ms combine --in three.txt
entropy: 00000000000000000000000000000000
phrase: abandon abandon ... about

# now only two
sed -n '1p;3p' shares.txt > two.txt
ms combine --in two.txt
error: not enough shares: have 2, need 3

2  Scratch a plate and watch it heal

That string below is a real wallet policy — the zen-hodl wallet from the third mission, one key that cannot spend anything younger than 32,768 blocks. Metal gets scratched, so the encoding carries error correction: it repairs up to four wrong characters and tells you exactly which. 

# four characters damaged (positions 5, 11, 18, 25)
md decode md1yqfdsqsjuqqpr5e55uzqqgqqqrqqvf4d7h59r2
md: codec error: codex32 decode error: BCH checksum verification failed

md repair md1yqfdsqsjuqqpr5e55uzqqgqqqrqqvf4d7h59r2
# Repair report
#   md1 chunk 0: 4 corrections at position 5: 'q' -> 's', position 11: 'p' -> 'c',
#                position 18: 'z' -> 'q', position 25: 'r' -> '6'
md1yqfdsssjuqqcr5e55uqqqgqqq6qqvf4d7h59r2

3  Check the device's work against a second implementation

The repaired string is that same zen-hodl wallet. Ask the command-line tool for its identity, and compare it with what the device showed you after mission 3. The device's firmware is Go; this tool is Rust. They were written to the same specification and never share a line of code. 

md inspect md1yqfdsssjuqqcr5e55uqqqgqqq6qqvf4d7h59r2
template: tr(50929b74...ac0,and_v(v:pk(@0/<0;1>/*),older(32768)))
wallet-descriptor-template-id: 73c33a5dea17b45376a6246995df0cbb
wallet-policy-id:              891b6c372c99c033c98bc80604deb6f0

Two independent implementations agreeing, to the bit, on what your wallet is. That is the whole point of a template identity.

Bonus  Try to do it the dangerous way

This one is meant to fail. Paste it and the tool refuses before it parses anything — the command is complete on purpose, so the refusal is real. 

ms split --phrase "abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about" -k 3 -n 5
ms: argument 3 on ARGV is a BIP-39 mnemonic, 93 characters long.
      Refused BEFORE the command line was parsed; nothing was read
      and nothing was written.
      ... `ps` shows it, and your shell has ALREADY written the line
      to its history.
A word on what this is. SeedHammer II engraves wallet backups into steel. The policies you build here are real BIP-388 wallet policies; the plate strings are real; the error correction is real. What's emulated is the machine — the screen, the buttons, the motion of the cutter.
