## The first task is DONE — do not rebuild it

**The simulator plate overlay shipped 2026-08-11**, fork `77774ec` ("emu: draw
the plate's layout while it cuts, and home as the machine does"). The layout is
drawn from the plan the moment the cut begins and the decoded step stream marks
progress on top of it. Six tests in `cmd/emu/plate_test.go` cover the Go half,
`planPath` matches `internal/golden.Vectorize` byte for byte, and it was
confirmed in the browser — abort mid-"hello", hold to resume, and the resumed
strokes land on the plan.

**F-121 is CLOSED**, fixed as a prerequisite rather than a neighbour: the
emulator now homes, because the overlay cannot register without it. It is no
longer a trap to design around.

Two things that will otherwise cost a session:

- **`qaProgram` is unreachable in `cmd/emu`** — `NFCReader()` returns nil, so
  `shNFC.present("FOREVERLAURA!")` queues a record nothing consumes. Driving a
  real engrave in the emulator means going through a normal program, not QA.
- Everything above is already verified. **Re-verifying it is the exact
  over-investment the operator ruled against on 2026-08-12** (see the Phase
  policy at the top of `design/FOLLOWUPS.md`): test infrastructure is polish
  owned by v0.0.1, and functionality comes first.

## The Load Payload journey is DONE — do not rebuild it either

**Shipped 2026-08-12**, `design/journeys/SeedHammer-II-load-payload-journey.pdf`
(10 pages, commits `390d5fa` `2403d74` `bb290e7` `4674856`). Ten device frames
from the emulator's own framebuffer, an eleven-section host transcript, and the
twelve open findings folded in as its "Corrections to the two earlier journeys"
page plus a matching table in `design/journeys/README.md`.

Both corrections it was scheduled to make are made: SPEC §5.5's delivery
paragraph no longer says "NOT yet rehearsed" (it has been, and the paragraph now
names the HOST as the actor), and `me sysw pack --help` states the lowercase-hex
rule for `text:`/`pass:` bodies with the `xxd` one-liner.

**What it turned up, all filed:** F-153 (the refusal named a cause that had not
occurred — fixed; the 0-based record index stays open), F-154 (the tenth
program's carousel dot is drawn under the firmware version line), F-155 (the
home screen cannot tell you whether a payload is loaded — a §3.1 spec question,
since an indicator has an argument against it too), F-156 (**neither published
journey could be regenerated by its own README's commands** — fixed).

Two things that will otherwise cost a session, both learned here:

- **`design/journeys/out/` and `shots/` are gitignored now**, and the emulator
  half needs three processes: `cmd/emu/build.sh` inside the flake, an
  `http.server` on **8731**, and `shot_server.py` on 8732 pinned to that origin.
  The frame names the builder expects are in `build_pdf_payload.py`.
- **A pipe eats the exit code.** `nix … | head -2` reported `[exit 0]` for a
  `nix: command not found` in the very transcript whose header says it avoids
  F-147. Never put a pipe between a command and `$?`.

## No task is pre-selected — these are the candidates

Both scheduled tasks are finished, so the next one is the operator's call. Their
state is recorded here so it does not have to be re-derived; ordered by what I
would argue for, not by what is decided.

- **F-150 — the on-device wallet-descriptor builder.** Operator's words: *needs
  major attention*. It dead-ends (blank screen after Next), assumes the user has
  exactly one key, and offers none of taproot, `after()`, `older()`, or
  `hash()`. Filed as needing its own brainstorm. **The largest known
  functionality gap on the device**, and the one a journey cannot paper over.
- **The remaining journeys.** Three documents exist in `design/journeys/`;
  **seven of the ten programs appear in none of them.** The toolchain is now
  known-good — the pathological pair was repaired (F-156) and
  `build_pdf_payload.py` is the corrected pattern, so the next document is
  mostly capture rather than plumbing.
- **F-155 → §3.1** — whether the home screen should say a payload is loaded.
  Small, but it is a spec ruling before it is a screen, and it pairs with F-152.
- **F-152 — selecting "from payload" when a payload is PRESENT BUT NOT LOADED
  should launch the loader.** Agreed as a feature; deliberately not implemented
  freehand. Needs a spec §3.1 state and one plan stage.
